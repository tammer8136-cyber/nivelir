# Поверка нивелира

Полевое приложение для определения угла i (главного условия) компенсаторного
нивелира и его юстировки сеткой нитей.

## Как запустить

Проект содержит только `lib/`, `test/`, `assets/`, `pubspec.yaml` и
`android/app/src/main/AndroidManifest.xml`. Платформенные папки не создавались —
их проще сгенерировать локально:

```bash
flutter create --platforms=android,ios --project-name nivelir_app .
# сгенерированный AndroidManifest.xml перезаписать тем, что лежит в репозитории
flutter pub get
flutter test
flutter run
```

`flutter create` в существующей папке не трогает `lib/`, `test/` и
`pubspec.yaml`, но перезапишет манифест — поэтому его нужно вернуть.

### Что было исправлено против первоначальной спеки

1. **3″/5″ — не допуск на угол i.** Это предельное расхождение отдельных
   значений угла между приёмами (критерий повторяемости), и живёт оно в
   ГКИНП 03-010-03, приложение 9. Допуск на саму величину угла — 10″, и это
   подтверждают три действующих источника: ГОСТ 10528-90 п. 2.3,
   ГКИНП 17-195-99 п. 4.2.5 и то же приложение 9.
2. **Сборник ГКИНП 1985 года утратил силу.** ГКИНП (ГНТА) 17-195-99
   (приказ Роскартографии от 17.06.1999 № 80-пр, введена 01.10.1999)
   отменила ГКИНП 17-195-85 ÷ 17-199-85, включая 17-196-85 по нивелирам.
   Ссылок на неё в коде и справке нет.
3. **Три приёма по умолчанию.** ГКИНП 17-195-99 п. 4.2.5 требует не менее
   трёх приёмов в любом способе. Один приём доступен как экспресс-проверка
   и помечается в протоколе как не соответствующий нормативу.
4. **Классификация по СКО** бралась из уровенной колонки ГОСТ (0,5 / 3,0).
   Приложение работает с компенсаторными приборами, у них колонка
   0,3 / 2,0 / 5,0. Девять записей каталога из 53 при этом сменили класс
   с «точных» на «технические».
5. **Геометрия описывается расстояниями до реек A и B**, а не «до ближней и
   дальней». В способе с разными плечами рейки меняются ролями между
   станциями, и привязка к расстоянию ломает знак превышения. Заодно это
   развязало противоречие в исходной спеке, где схема БД и формула юстировки
   подразумевали противоположные соглашения о знаке.
6. **ISO 17123-2 убран из пресетов** (отложен до v2): там база 60 м, станции
   30/30 и 10/50, по десять измерений в наборе, а критерий — разность средних
   превышений против допуска ISO 4463-1, а не угол i.

## Расчётное ядро

Соглашение о знаках — одно на всё приложение:

```
h = отсчёт_по_рейке_A − отсчёт_по_рейке_B
h_измеренное = h_истинное + i · (s_A − s_B)

i = (h₂ − h₁) / [(s_A₂ − s_B₂) − (s_A₁ − s_B₁)]
```

Знаменатель по способам: 50 м у рабочего метода с базой 100 м, удвоенная длина
линии у способов «вперёд» и «с разными плечами». Формула проверена на числовом
примере ГКИНП 17-196-85, табл. 4 (см. `test/collimation_test.dart`).

В способе «вперёд» плечо, равное нулю, означает, что нивелир стоит над точкой:
вместо отсчёта по рейке вводится высота визирной оси, измеренная рулеткой.

## Архитектура

Донор — `drainage_app` (Flutter): из него взяты структура `database_service`,
подход к PDF-экспорту с TTF-шрифтами для кириллицы, `settings_service` поверх
`shared_preferences` и разметка темы. Код написан заново, не форк.

```
lib/
  models/          Device, Verification (+Run), Reminder, MethodPreset/Geometry
  services/
    nivelir/algorithms/  collimation.dart, classification.dart — чистая математика
    database_service.dart    sqflite: devices, verifications, verification_runs, reminders
    export_service.dart      PDF-протокол
    excel_export_service.dart журнал .xlsx, строка на приём
    notification_service.dart неточные будильники
    settings_service.dart
  state/           AppSettings (мм/м, флаг подготовки), WizardState
  screens/         home, wizard/ (6 шагов), devices/, history, settings, help/
  data/            help_articles.dart — тексты справки
  utils/units.dart конвертация и форматирование
```

### Правило, которое нельзя нарушать в мастере

`PageView` уничтожает ушедшие за экран страницы вместе с их локальным
состоянием. Поэтому:

1. `TextEditingController` создаётся **только** в `WizardState`, никогда — в
   `State` виджета шага.
2. Виджет шага читает контроллер через `context.read<WizardState>()`.
3. `TextFormField(initialValue:)` запрещён — только `controller:`.

Прокрутка `PageView` отключена: переход только по кнопкам, чтобы шаг нельзя
было пролистнуть мимо валидации. Системный «назад» перехвачен `PopScope` и
возвращает на предыдущий шаг.

## Решения по данным

- Отсчёты хранятся в **целых миллиметрах**; тумблер мм/м — только формат
  ввода-вывода, конвертация собрана в `utils/units.dart`.
- `tolerance_arcsec_snapshot` — снимок допуска на момент поверки. Правка
  custom-прибора не меняет задним числом исторические вердикты.
- Протоколы не удаляются вместе с прибором: `device_label` денормализован,
  внешнего ключа на `devices` намеренно нет. Удаление custom-прибора — без
  подтверждений.
- Каталог из `assets/devices_catalog.json` засевается один раз при первом
  запуске. Поля `gost_class` и `i_angle_tolerance_arcsec` из JSON
  **игнорируются**: класс считается из СКО в коде, чтобы правило жило в одном
  месте.
- Напоминания — по конкретному прибору, по умолчанию выключены, планируются
  неточными будильниками (не нужно `SCHEDULE_EXACT_ALARM`).

## Что осталось

- Иконка и splash.
- Веб-персистентность (в мобильной сборке не нужна).
- ISO 17123-2 отдельным режимом.
- Проверка смещения визирной оси при перефокусировке (ГКИНП, п. 3.2.7) —
  актуальна как раз для работы с неравными плечами.
